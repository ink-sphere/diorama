# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Diorama** is an ebook reader that extracts structured "world models" from ebook content using LLMs (v0.0.1). The codebase is a working vertical slice, not a stub: a Next.js **shelf UI** (`frontend/`) talks to a FastAPI **backend** (`diorama/backend/`) that, on upload, runs an EPUB through two ReAct **agents** (`diorama/agents/`) built on a UI-agnostic **agent framework** (`diorama/core/`) and a deterministic **EPUB parser** (`diorama/ebook/`), streaming their live progress back to the browser over SSE while the book lands on the shelf. Processing is two phases: the **loader** maps the book's hierarchy, then the **scene segmenter** runs once per leaf section to mark the scene boundaries a future illustration will hang on.

`pyproject.toml` still declares `sqlalchemy`, `asyncpg`, `alembic`, `pillow`, and `typer`, none of which are imported anywhere — there is no database (the backend is a JSON-file store) and no CLI entrypoint (no `[project.scripts]`, no `__main__`). `books/` (sample `.epub` files) and `.diorama_data/` (`library.json`, `uploads/`, `structures/`, `scenes/`, `covers/`, `usage/`) are gitignored runtime data — `.diorama_data/sessions/` is also where `JsonlSessionStore` writes agent session logs when configured, so that directory name is dual-purpose. There is no book-detail page, and illustrations are a reserved slot rather than something the backend generates — scene *boundaries* exist (`scenes/{id}.json`), scene *pictures* do not.

## Architecture

### `diorama/core/` — the ReAct agent framework

`ReactAgent` (`react.py`) is the orchestrator. It owns the message history (OpenAI chat format), a `ToolRouter`, a `LiteLLMModel`, and optionally a `JsonlSessionStore` and a `ContextCompactor`. Its loop is an **async generator that yields typed events** rather than printing or returning directly — presentation is fully decoupled from the agent loop:

- **Tools**: `Tool`/`ToolParameter` (`tool.py`) are pydantic models a tool subclasses, overriding only `forward()`; `to_json_schema()` builds the OpenAI function-calling schema. `ToolRouter` (`router.py`) is a pure registry — it tracks which tools are `active` (visible to the model) vs deferred, builds the tool-spec payload sent to the LLM, and dispatches calls via reflection on `forward`'s signature (injecting `tool_call_id`, `signal`, `on_update` only if the tool declares them).
- **Deferred tool discovery**: tools can register with `active=False` and stay hidden from the model's schema until another tool's result returns `added_tool_names`, which activates them for the next turn — used to keep a large toolset out of the prompt until relevant.
- **Results**: `Tool.forward` returns a `ToolResult` (or a plain value, auto-coerced) — see `results.py`. `ToolResult` carries `is_error`, `details` (never sent to the model, only surfaced in events/logs), `added_tool_names`, `images` (attached as a separate follow-up `user` message with `image_url` parts, since the Chat Completions tool-result slot is text-only), and `terminate` (ends the run from inside a tool).
- **Events**: `events.py` defines the full typed union (`AgentStart/End`, `TurnStart/End`, `MessageStart/Update/End`, `ToolExecutionStart/Update/End`, `CompactionStart/End`, `RetryEvent`). Subscribe via `ReactAgent.subscribe()` (sync or async listeners), or consume `stream_events()`/`agent.last_result` directly (the pattern `EbookLoaderAgent.stream_load()` mirrors — see below). `ConsoleRenderer` (`rendering.py`) is the built-in Rich-based subscriber; the loop itself never touches a console or an HTTP response.
- **Sessions**: `JsonlSessionStore` (`session.py`) is an append-only JSONL **tree**, not a list — every entry has a `parent_id`, so branching/resume is just moving the "active leaf" pointer. `reset()` starts a new root without deleting history; `branch(entry_id)` rewinds the leaf without deleting the abandoned path.
- **Context management**: `ContextCompactor` (`context.py`) is consulted before every turn. When a deterministic token estimate crosses a threshold, it summarizes the older half of history via an LLM call and replaces it with a synthetic message, keeping a verbatim tail that never starts on a `role: tool` message (to avoid orphaning a tool result from its assistant call).
- **Cancellation**: `CancellationToken` (`cancellation.py`) is **cooperative, not preemptive** — polled mid-stream, between tool calls, and at turn boundaries. On stop, every orphaned tool call is answered with a synthetic interrupted-tool-result so history stays valid for the next request; this repair also runs proactively at the start of every run in case a previous run crashed mid-flight.
- **Hooks**: `before_tool_call`/`after_tool_call` run around every tool dispatch; `after_tool_call` sees every outcome, including blocked or failed calls.
- `answer.py` (`FinalAnswerTool`) and `demo_tools.py` (`CalculatorTool`, `CurrentTimeTool`) are example/utility tools. `prompts.py` holds `SYSTEM_PROMPT`.

**Design invariants worth knowing before touching `react.py`:**
- A turn ends when the model returns **no tool calls**; `final_answer` is an optional convenience tool the system prompt encourages, never a required termination signal.
- Anthropic's **signed `thinking_blocks`** must be stored on the assistant message and replayed verbatim on subsequent requests, or the provider rejects the conversation once extended thinking is engaged. Plain `reasoning_content` text is output-only and always stripped before sending. `preserve_reasoning=False` strips thinking blocks too (smaller context, but breaks continuing extended thinking).
- A streaming completion can only be retried if it produced **zero** output so far — once any delta has arrived, a retry would duplicate it, so the exception is re-raised instead.
- `finish_reason` of `length`/`max_tokens`/`content_filter` stops the run without executing that turn's tool calls, since their arguments may be truncated.
- Error classification for retries prefers exception type (e.g. `litellm.RateLimitError`) over string-matching `str(error)`, to avoid false positives from quoted status codes in error text.

### `diorama/models/` — LLM wrapper

- **`litellm_model.py`** — `LiteLLMModel`: async chat completion wrapper (`acompletion`) used by `ReactAgent`. Tracks cumulative usage (prompt/completion/cache tokens) and cost per call (`record_usage`, `cumulative`). It is also **the single chokepoint every LLM call in the app passes through** — agent turns and compaction summaries alike — which is why per-call cost tracking is instrumented here and nowhere else: `record_usage` prices a call and emits an `LLMCallRecord` to the optional `usage_sink`, and `record_failure` does the same for an attempt that errored. With no sink installed nothing is stored and behaviour is exactly as it was before the dashboard existed, so `diorama/core/` keeps having no persistence concern. Sink exceptions are swallowed and logged: an unwritable ledger must never take down a book that is otherwise processing fine.
- **`providers.py`** — the registry of places a model can be routed: today `openrouter` (`openrouter/…`) and `google` (Google AI Studio, `gemini/…`). Imported by the settings store, the catalogue and the pricing cascade, so adding a third is one entry plus a catalogue fetcher. **A model id names its own provider** — `provider_for_model()` works backwards from the litellm prefix — which is why there is no global "current provider" anywhere in the app: choosing the model is choosing the provider, and the key follows. An unrecognised prefix (`anthropic/claude-…`) resolves to *no* provider and therefore no Diorama-held key, leaving litellm's own environment lookup in charge rather than handing it the wrong credential.
- **`pricing.py`** — two rate tables behind one `ModelPricing` shape. `PricingTable` fetches live per-model pricing from OpenRouter with a 24-hour disk cache; `litellm_pricing()` reads litellm's bundled static cost map, which covers what OpenRouter never sees (every direct `gemini/` call). **It reads the whole map, not two fields of it**: `litellm.cost_per_token()` answers prompt+completion only, so pricing through it charges every cache-read token at the fresh-input rate — for an agent loop replaying a growing transcript that is most of the tokens, and it overstated long runs several-fold. `cost_model_candidates()` is the shared id-fallback ladder (`openrouter/x/y` → `x/y` → `y`). `litellm` is a hard dependency here (no optional-import fallback).
- **`google_pricing.py`** — a **hand-maintained** per-token rate table for Gemini, consulted first for a direct `gemini/` call as a hand-verified *override*; anything it hasn't caught up with (the whole 3.1/3.5/3.6 generation, at time of writing) falls through to `litellm_pricing()`, which still prices cache reads properly. Google publishes no machine-readable price list, and litellm's map knows only prompt/completion — but cached input is most of what a long agent transcript costs, and pricing a cache read as a fresh prompt token overstates a run several-fold. Rates are paid-tier, standard-context (so a >200k-token run under-estimates, never over-), and an unlisted model falls through to litellm rather than erroring. `reasoning` is deliberately **0.0**: litellm folds `thoughtsTokenCount` into `completion_tokens` before Diorama sees it, so a non-zero rate would bill thinking tokens twice.
- **`prompt_cache.py`** — Anthropic prompt-cache breakpoints (`apply_prompt_caching`): marks the end of tool specs and a rolling message-window boundary. Never mutates input objects — always returns shallow copies with cache markers added. No-op for non-Anthropic providers; extracts cache tokens from both Anthropic- and OpenAI-shaped usage payloads.
- **`usage.py`** — `LLMCallRecord`: the durable per-call ledger row behind the cost dashboard, plus the provenance helpers that fill it in (`split_model_id`, `extract_route`, `read_provider_field`/`extract_provider`, `provider_label`, `call_timer`). Holds **`route` and `provider` as separate fields on purpose**: `route` is the API being billed (`openrouter`, or `gemini` for a direct Google AI Studio call), `provider` is the upstream that actually served the tokens — OpenRouter load-balances that per request, and collapsing the two would make Gemini-billed-direct indistinguishable from Gemini-via-OpenRouter, which are different invoices for the same model. `read_provider_field` checks all three places litellm may surface an unknown field (attribute, `model_extra`, `_hidden_params`); `extract_provider` adds the model-id vendor as a fallback, which is correct for a direct call since you are served by whoever you called.
- **`catalogue.py`** — one fetcher per provider behind the picker, each with its own 24h disk cache. `list_models()` reads OpenRouter's `/api/v1/models` (id, display name, context length, prices, `supports_tools`); `list_google_models(api_key)` reads Google's paginated `v1beta/models`. Deliberately *not* folded into `pricing.py` even though OpenRouter's half reads the same endpoint: `pricing.py` caches only the per-token rates keyed by model id, and two independent caches mean a stale picker can't invalidate live pricing. **The two providers are not symmetrical**, and `ModelInfo` carries the asymmetry: Google's list needs a key (`list_google_models(None)` is `[]`, not even a cached list), reports no prices (so `prompt_price` comes from `google_pricing` and `pricing_known` is False when it can't, since a picker printing "Free" for a rate it doesn't have is worse than one printing nothing), and has no function-calling flag (so `supports_tools` is inferred by *denylist* — `gemma`, `imagen`, `veo`, `tts`, `image`, `embedding`, `aqa` — which errs toward listing a model with a caveat rather than hiding it). Best-effort throughout — an unreachable API falls back to a stale cache, then to `[]`, and the picker degrades to free-text entry.

### `diorama/ebook/` — deterministic EPUB parsing & structure slicing

No LLM/agent dependency anywhere in this package — everything here is pure, testable logic.

- **`parser.py`** — `EbookContext.parse()` flattens an EPUB's spine documents into numbered `Block` objects (paragraphs/headings/list items, in reading order) via BeautifulSoup; this block-id sequence is the coordinate system every tool and the agent itself operate on. Also builds a block-anchored table of contents from the EPUB's own `book.toc`, resolving anchors exactly where possible and falling back to fuzzy title matching (`thefuzz`) against headings.
- **`models.py`** — `Block`, `TocEntry`, `StructureNode` (a leaf carries `text`/`segments`; a branch's range must exactly span the union of its children's ranges), `Coverage`, `EbookStructure`.
- **`slicer.py`** — `validate_tree()` / `build_structure()` deterministically turn an agent-submitted tree of block-id boundaries into an `EbookStructure`. A single internal tree walk (`_walk`) backs both validation and coverage computation, so they can't drift apart. `child_pattern` auto-expansion: a regex matched against the start of block text generates repeating children (e.g. "SCENE I", "SCENE II") without the agent listing each one by hand; any blocks before the first match become that node's `preamble_text`.

- **`scenes.py`** — the same two-phase split, one level down: `validate_scenes()` / `build_scenes()` turn an agent-submitted list of `[start_paragraph, end_paragraph]` boundaries into a `SceneSegmentation` for one leaf node (`Scene` / `SceneSegmentation` / `BookScenes` live here, not in `models.py`). **`split_paragraphs()` is a plain `str.split("\n\n")`** — no stripping, no regex, no dropping empties — so `join(split(text)) == text` for *any* input and a scene's text is always a verbatim substring. That property is the whole point ("the core text must not change"), and a "smarter" splitter would silently break it. `validate_scenes` demands an exact partition (first scene at 0, last at the final paragraph, contiguous throughout), so no paragraph is orphaned between two illustrations or claimed by both. `single_scene()` is the no-LLM fallback, and `iter_leaves()` walks a structure's leaves in the same depth-first order the frontend's `readBook()` uses.

### `diorama/agents/` — `EbookLoaderAgent`

`ebook_loader.py` builds a **fresh `ReactAgent` per book** (`_build_agent`), bound to read-only tools over that book's parsed `EbookContext` (`get_overview`, `get_toc`, `list_headings`, `read_blocks`, `search_blocks`) plus `submit_structure`, which validates via `diorama.ebook.slicer.validate_tree` and only terminates the run (`ToolResult(terminate=True)`) on success — a rejected submission returns validation errors and the agent must retry.

Two entry points share `_build_agent`/`_finalize`:
- **`load()`** blocks to completion and returns the `EbookStructure` (raises `EbookLoaderError` if the run ends without one).
- **`stream_load()`** returns `(events, finalize)`, mirroring `ReactAgent.stream_events()` + `last_result` — iterate `events` fully, then call `finalize()`. This is what `diorama/backend/processing.py` consumes to fan the run's live events out over SSE instead of blocking.

The compaction reserve is bumped to 48k tokens (see the comment above `_COMPACTION_RESERVE_TOKENS`) because the default chars/4 token estimate undercounts these transcripts, which are dense with `[Block N]` markers. The module-level `_DEFAULT_MODEL_ID` (`openrouter/google/gemini-3.6-flash`) is only the no-backend fallback for a directly-constructed agent — the backend resolves per provider and passes an id explicitly. Running the agent for real costs tokens/money and is never exercised by the offline test suite, which drives `ReactAgent` via `tests/fakes.py`'s scripted fakes instead.

### `diorama/agents/` — `EbookSceneSegmentationAgent`

`ebook_scene_segmentation.py` takes one *leaf* `StructureNode` and marks where, within its text, the picture would change. Its coordinate system is **paragraph indices into that node's text**, not block ids — two tools only (`read_paragraphs`, `submit_scenes`), and `submit_scenes` validates the partition before accepting it, so a gap/overlap comes back as errors to fix and only a valid submission terminates the run. The agent never emits book text; `build_scenes` slices it back out.

Entry points mirror the loader's: `segment_text()` / `segment_node()` block, `stream_segment_node()` returns `(events, finalize)`, and `segment_structure()` walks every leaf sequentially. Two things are deliberate: **nodes under `DEFAULT_MIN_PARAGRAPHS` (3) skip the model entirely** (`single_scene()` — paying an LLM to confirm a half-title page is one picture buys nothing), and **per-node cost is a `cumulative` *difference*, not a read**, because one model instance can span a whole book and reading its running total would bill every node for the book so far. The opening prompt inlines the node's numbered text up to `_INLINE_CHAR_BUDGET` (24k chars) and tells the agent to page through the remainder with `read_paragraphs`.

### `diorama/backend/` — FastAPI app (the library API)

- **`main.py`** — FastAPI app; CORS restricted to `http://localhost:3000`. `load_dotenv()` runs before the router import so `OPENROUTER_API_KEY` is set before any agent code loads.
- **`store.py`** — a JSON-file library store, not a database (despite `sqlalchemy`/`asyncpg`/`alembic` sitting unused in `pyproject.toml`). A single `asyncio.Lock` guards read-modify-write of `.diorama_data/library.json`; `uploads/{id}.epub` and `structures/{id}.json` live alongside it. This reuses the exact directory layout a removed prior implementation left behind.
- **`trace.py`** — translates `diorama.core.events.AgentEvent` into small `TraceLine` rows (`kind`: status/thinking/tool/done/error; `status`: pending/done/error) for the frontend. Deliberately hides raw tool JSON (block/TOC dumps) behind short human phrasing (`_TOOL_DONE_VERBS`) rather than showing it verbatim — a past iteration of this file did dump raw JSON to the trace pane, which is the failure mode to avoid if extending it.
- **`processing.py`** — **two phases per book, sharing one ledger `run_id`**: the loader (every move translated to a `TraceLine`), then scene segmentation (`_segment_scenes`, `SCENE_CONCURRENCY = 4` sections at a time). Phase two reports through a **single re-published `kind="progress"` line** (`scenes-{book_id}`) carrying `done`/`total` — dozens of agent runs nobody wants a trace of, so the frontend draws a bar instead. Only phase one is load-bearing: the structure is saved *before* segmentation starts, a section that won't segment falls back to one whole-section scene, and a wholesale phase-two failure still shelves the book as ready. `book.cost_usd` is read back from the ledger (`run_cost`) rather than off the structure, so it covers both phases. Also: one `_BookRun` per `book_id`, **in-memory only** (`ensure_started()` starts a background task the first time anyone opens that book's stream). Each `_BookRun` holds the accumulated log plus a list of subscriber `asyncio.Queue`s, so a late subscriber (page refresh, second tab) replays the whole log then joins the live tail. Restarting the server loses in-flight runs, but the *next* `/stream` request for that book re-triggers processing from the saved upload file — self-healing, not a bug. Level-type counts are tallied and singularized across the tree (`_tally_levels`/`_singularize`) before display, because the agent doesn't always pick a consistent singular/plural `level_type` across nodes. Raw `EbookLoaderError` text is stripped of its class-name/agent-speak preamble (`_user_facing_error`) before reaching the user.
- **`routes/books.py`** — `GET/POST /api/books`, `GET /api/books/{id}`, `POST /api/books/{id}/retry`, `DELETE /api/books/{id}`, `GET /api/books/{id}/stream` (SSE, `text/event-stream`), plus the four the reader depends on: `GET /api/books/{id}/structure` (the saved `EbookStructure`; **409** — not 404 — when the book exists but hasn't finished processing), `GET /api/books/{id}/scenes` (the saved `BookScenes`; **404 is the normal answer** for a book shelved before segmentation existed or one whose phase-two failed — 409 is reserved for still-processing, where asking again later works), `GET /api/books/{id}/cover`, and `PATCH /api/books/{id}/progress`.
- **Covers** — `diorama/ebook/cover.py`'s `extract_cover()` is a cascade of heuristics (EPUB 3 `properties="cover-image"`, the EPUB 2 `<meta name="cover">` pointer, ebooklib's `ITEM_COVER`, then a filename guess) because EPUBs declare covers four incompatible ways. Results are cached under `.diorama_data/covers/{id}.{ext}` — including *absence*, as a `.none` marker, since the shelf requests every book's cover on every load and re-parsing a coverless EPUB each time is the failure mode that caching exists to prevent.
- **`settings.py`** — per-agent model config plus one credential per provider, persisted to `.diorama_data/settings.json` (chmod 600 — it holds the API keys in plaintext, same trust model as the `.env` the process already reads). **Every value resolves settings → environment variable → built-in default**, which is what makes the settings page additive: an existing `.env` keeps working and a UI-saved value simply shadows it. **There is no "current provider" setting**: `api_keys` is a dict keyed by provider id, and `resolve_agent_runtime()` hands an agent the key belonging to the provider *its model id names*, so the loader can run on Gemini while a later agent runs on OpenRouter. A file written before Google existed (one `provider`, one `api_key`) is folded into `api_keys` by a `model_validator(mode="before")` — read in place, no migration step to fail. `AGENTS` is the registry of configurable agents (`ebook_loader` and `ebook_scene_segmentation`), each resolving its model independently — so the segmenter, which runs once per section, can point at a cheaper model than the loader. Adding a third is a registry entry, not a migration. **Defaults are per provider, not one per agent** (`default_models`, resolved by `resolve_default_model_id()`): an unconfigured agent falls back to the default belonging to the first provider — registry order — the install holds a usable key for, and only to `fallback_model_id` when there is no key at all. This is not hypothetical tidiness: the scene segmenter shipped with a single OpenRouter default onto a Google-only install, resolved to a model it had no credential for, and 401-ed on every section *silently*, because its failures are deliberately non-fatal. `AgentView.default_model_id` is therefore this install's default rather than a constant — it labels the Reset control, so it has to be what clearing the field would really produce. The API-facing `SettingsView` carries only *masked* keys (`sk-or-v1…a4f2`), so a saved key can't be read back out of the API — and `SettingsUpdate` is therefore a **sparse** write for both dicts: an absent entry means "unchanged" (the form only ever received a mask and a possibly-inherited model id), an **empty string** is the explicit erase. `configured_model_id` (what's saved) is reported separately from `model_id` (what will actually run) so the UI can distinguish "you chose this" from "this came from your .env", and so pressing Save on an untouched form writes nothing.
- **`usage_store.py`** — the per-book cost ledger and the rollups the dashboard renders. Each LLM call is appended as it completes to `.diorama_data/usage/{book_id}.jsonl`, never rewritten. **Append-only per book** is the load-bearing choice: a run that dies halfway still leaves an accurate account of what it already spent (a record written only on success would systematically under-report exactly the runs that went wrong), deleting a book stays one sweep of its id, and a sink called from inside the async agent loop never has to parse what's already on disk. The cost is that aggregation is a full scan folded in Python rather than a `GROUP BY` — fine at a personal shelf's scale, and the record shape is already the row shape a table would want. **Reprocessing appends a second run** rather than replacing the first, so a retry's cost is its own line item. `run_cost()` exists so a *failed* run can still report what it spent: the agent raises before its cumulative totals can be read, but the ledger already has every call. Providers are grouped case-insensitively (`OpenAI` from OpenRouter and `openai` from a model id are the same payer), and `UsageTotals` separates `calls` (every recorded attempt) from `billed_calls` (the ones that actually charged) so retries neither inflate the count nor vanish.
- **`routes/usage.py`** — `GET /api/usage` (the overview: totals, per-model/provider/route/agent/kind breakdowns, the daily trend, and a row per book) and `GET /api/usage/books/{id}` (one book's runs, breakdowns, and every call). A **404 on the latter is the normal answer for a book processed before cost tracking existed**, not a fault — the frontend says so rather than showing an error. An empty overview is likewise a normal fresh-install outcome.
- **`routes/settings.py`** — `GET/PUT /api/settings`, `GET /api/settings/models` (**only connected providers' models**, merged, plus a per-provider `CatalogueStatus` — `needs_key` is what separates "you haven't connected this one" from "we couldn't reach them", and an empty list is a normal outcome either way, not an error). A provider with no resolvable key contributes nothing *even though OpenRouter's catalogue is public* — that gate is a policy, not a limitation: a model Diorama can't authenticate is one that fails halfway through the first book, so the picker lists what this install can run rather than what exists, `POST /api/settings/test` (**per provider**: OpenRouter's `/api/v1/key`, which also reports spend, versus Google, where listing models *is* the check and no balance exists to report — so those fields stay null rather than showing zeros that read as "nothing spent"). Test warnings are scoped to the agents actually routed through the provider under test, and warn when a configured model is unlisted or can't call tools — the ebook loader is nothing but tool calls, so a tool-less model fails only once a book is halfway processed.
- **Reading position** — `BookRecord.progress` (`ReadingProgress`) is a (section, scene, page) triple in descending order of stability. `section_index` indexes the structure's leaves in depth-first order (the frontend's `readBook()` walk defines that order, so changing it invalidates saved positions); `scene_index` indexes that section's scenes and is optional (None for a book with no segmentation, and for positions saved before scenes existed); `page`/`pages` are only meaningful relative to the type size and viewport that produced them. `resolveRestore()` falls through all three: the same page when the page count still matches, else the scene's first page, else a scaled ratio.

Run from the repo root: `uv run uvicorn diorama.backend.main:app --reload --port 8000`.

### `frontend/` — Next.js library + reader

Next 16 App Router, TypeScript, **Tailwind v4** (`@theme` tokens in `src/app/globals.css`, OKLCH, `@custom-variant dark` keyed to next-themes' class), **framer-motion** and **recharts** (cost charts only). Four routes: `/` (the shelf), `/read/[id]` (the reader), `/settings`, and `/costs` + `/costs/[bookId]` (the cost dashboard). Newsreader sets the book, Inter is confined to chrome.

- **`src/lib/`** — `api.ts` (the only place that talks to the backend), `types.ts` (hand-kept mirrors of the pydantic models), `structure.ts` (`readBook(structure, scenes?)` flattens an `EbookStructure` into linear `Section`s plus a `TocNode` tree, grouping each section's paragraphs into `scenes`), `usePagination.ts`, `useReaderPrefs.ts`, `useMediaQuery.ts`.
- **`components/library/LibraryView.tsx`** is the shelf orchestrator and the only owner of SSE: one `EventSource` per in-flight book, and trace lines merged **by id** rather than appended — a tool call's pending and done events share one id (the `tool_call_id`) so the row updates in place. (A prior version appended, which caused a React duplicate-key collision; watch for this if changing the trace payload shape.) It also optimistically flips a book to `"processing"` on its first streamed event instead of waiting for a refetch. Merge-by-id is also what makes the scene-segmentation bar work: the backend re-publishes one `kind="progress"` line whose `done`/`total` climb, and `TraceLog.tsx` draws it as a bar instead of a log row.
- **`components/reader/`** — `ReaderView.tsx` (position, restore, progress saving, keyboard nav), `Spread.tsx` (the sheet: text verso, plate recto), `TocSidebar.tsx`, `TypeMenu.tsx`, `ReaderChrome.tsx`.
- **Pagination is measured, not estimated** (`usePagination.ts`): the section's text is laid out in a CSS multi-column box whose column width is the page width and whose height is the page height, so the browser does the line breaking; one column is one page and a page turn is a translate on `x`. **A scene is the page unit**: each scene is a block carrying `.scene-break` (`break-before: column`), so it always opens a page, overflows onto as many as it needs, and the next scene starts on the page after it ends — the browser fits scenes to columns exactly as it fits words to lines, and nothing computes a break. `scenePages` is measured the same way, from each `[data-scene]` element's `offsetLeft` (which reports its *first* fragment, so a scene spanning three columns still answers with the one it opened in). The column width is applied to the element **imperatively, in the frame it's measured in** — routing it through React state would need a second render before `scrollWidth` meant anything. The measurement signature must include the section's own identity (`startBlockId`), or the first measure runs against an unmounted spread and never re-runs, leaving one over-long page.
- **`structure.ts` quirks worth knowing**: scenes are re-split from each `Scene.text` rather than applied by `start_paragraph`/`end_paragraph` — the indices are into the backend's bare `"\n\n"` split, while `toParagraphs()` trims and drops empties and `stripRepeatedHeading()` removes leading ones, so an index would drift; segmentations are keyed by `start_block_id`, not by position, because a branch node with `preamble_text` emits an extra "Opening" section that is not a leaf and has no segmentation. `stripRepeatedHeading()` drops leading paragraphs that merely restate the heading, because a section's block range starts *at* the chapter's own `<h1>` and would otherwise print it twice and steal the drop cap; `headingFor()` avoids "Chapter II: CHAPTER II. The Pool of Tears" by checking whether the title is already labelled; `titleCase()` turns the agent's snake_case `level_type`s ("front_matter") into display labels.
- **`components/costs/`** — `CostsView.tsx` (the `/costs` overview), `BookCostView.tsx` (one book's trace, down to a table of every call with an expandable per-row detail), `Charts.tsx` (recharts wrappers), `Primitives.tsx` (stat tiles, panels, the cost-by-type bar) and `format.ts`. Reached from the bars icon in the shelf header, and from the cost figure on each book card. Things done deliberately: series colours are emitted as **`var(--chart-N)` strings, not resolved values**, so a theme toggle recolours the SVG with no React work; bar animation is **off**, because recharts replays the grow-in on every resize and expanding a call row would otherwise make unrelated charts flicker; money is formatted **per magnitude** (`$0.0042` vs `$12.40`) since a fixed two decimals renders most real per-call figures as `$0.00`, which reads as free rather than small; and a book with no recorded cost shows *nothing* rather than `$0` — unmeasured and free are different claims.
- **`components/settings/`** — `SettingsView.tsx` (one credential card per provider, then one row per agent; reached from the sliders icon in the shelf header) and `ModelPicker.tsx` (searchable combobox over every **connected** provider's models — OpenRouter's ~360 plus Gemini's, whichever have keys). There is **no provider selector**, because picking `gemini/…` for an agent is what routes it through Google; the page instead warns when an agent points at a provider with no key, and the picker's empty state distinguishes "nothing connected yet" (fixable here) from "couldn't reach them". Three things the picker deliberately does: it filters to **tool-capable models by default** (a tool-less model is a silent trap for the loader), it offers a provider chip row so a dozen Gemini models aren't buried under hundreds of OpenRouter ones, and it always accepts a hand-typed model id — normalised against the known prefixes, defaulting to `openrouter/` for a bare id — so an unreachable catalogue degrades to a text field rather than blocking the page. Key drafts are **tri-state** (`undefined` untouched / a string / `""` staged clear), since the field starts empty whether or not a key is stored. A field is only "dirty" relative to what's *saved*, never to what's inherited — `configured_model_id`, not `model_id`, is the baseline, and only changed agents and touched keys go into the PUT payload.
- **Illustrations**: nothing generates images yet, so the recto is a designed, reserved plate slot (`PlatePage` in `Spread.tsx`) rather than a picture. When images exist, only the inside of the frame changes.
- No locked/gated chapters exist anywhere in the product — every TOC entry is navigable.
- **`frontend/AGENTS.md`** warns that this Next.js version (16.x) has breaking changes versus training data — read `node_modules/next/dist/docs/` before writing frontend code that touches routing, fonts, metadata, or other framework conventions. Note `params` is a `Promise` and `PageProps<'/read/[id]'>` is a global helper. ESLint runs the React Compiler rules: **no synchronous `setState` inside an effect** — browser-only facts (media queries, mount state, localStorage prefs) are modelled with `useSyncExternalStore` instead.
- Needs `frontend/.env.local` with `NEXT_PUBLIC_API_BASE` (defaults to `http://localhost:8000` if unset). Run with `npm run dev` inside `frontend/`.

### How the pieces connect: upload → shelf → reader

1. Frontend uploads an `.epub` → backend saves it to `uploads/{id}.epub`, creates a `BookRecord` (`status="queued"`), returns a `stream_url`.
2. Frontend opens an `EventSource` on that URL. The backend's `ensure_started()` starts a background task that calls `EbookLoaderAgent.stream_load()`.
3. Each `AgentEvent` is translated (`trace.py`) into a `TraceLine` and published to every subscriber of that book's `_BookRun`.
4. On success, the backend writes the `EbookStructure` to `structures/{id}.json` and updates the `BookRecord` (title/author/level-type breakdown/coverage/cost); on failure, it records a user-facing error **and the run's cost read back from the ledger** (`run_cost()`), then the frontend offers retry, which calls `POST /retry` then reopens the stream.
5. A ready book links to `/read/{id}`, which fetches the record and the structure, flattens the structure into sections, paginates the current one by measurement, and writes position back with `PATCH /progress` (debounced). Reopening the book restores that position, scaled into whatever pagination the current type size and window produce.

**Cost tracking rides alongside that flow, not inside it.** `processing.py` mints a `run_id` and hands `EbookLoaderAgent` a `usage_sink` bound to the book; the agent attaches it to the `LiteLLMModel` it shares with the `ContextCompactor`, so turns *and* compaction summaries both reach the ledger. Each call is priced and appended the moment it completes — `/costs` reads persisted state on load rather than streaming, so a refresh mid-run shows partial spend without any new SSE plumbing. Deleting a book deletes its ledger (`store.delete_book` → `usage_store.delete_usage`).

## Key Configuration

### Environment Variables

The model and key variables below are the **middle** rung of a three-step chain — `.diorama_data/settings.json` (written by the `/settings` page) shadows them, and they in turn shadow the built-in defaults. Neither file is required; an install with only a `.env` behaves exactly as it did before settings existed.

`.env` at the repo root (loaded via `python-dotenv`/pydantic-settings):
- `OPENROUTER_API_KEY` — authenticates any agent whose model id starts `openrouter/` (the default), unless a key is saved on the settings page.
- `GEMINI_API_KEY` — the same, for any agent whose model id starts `gemini/` (Google AI Studio, billed direct). Only consulted for `gemini/` models: which key a run uses follows from the model it was configured with, never from a global provider setting.
- `DIORAMA_LOADER_MODEL_ID` — optional; overrides the litellm model id `EbookLoaderAgent` runs with (resolved per run by `resolve_agent_runtime()` in `diorama/backend/settings.py`). With nothing set it takes the default for whichever provider you have a key for: `gemini/gemini-3.6-flash` on Google AI Studio, `openrouter/google/gemini-3.6-flash` on OpenRouter. A `gemini/...` id here routes the loader through Google AI Studio, and picks up `GEMINI_API_KEY` rather than `OPENROUTER_API_KEY`.
- `DIORAMA_SCENE_MODEL_ID` — the same, for `EbookSceneSegmentationAgent`, with the same per-provider defaults. It runs once per leaf section, so it is the one worth pointing at a cheap model.
- `DATABASE_URL`, `POSTGRES_PORT` — present in `.env` but currently unused; no database code exists.

`frontend/.env.local`:
- `NEXT_PUBLIC_API_BASE` — the backend origin the shelf UI calls; defaults to `http://localhost:8000`.

### Code Style

- **Target Python:** 3.12 per ruff config, though `requires-python` allows `>=3.10` — be mindful of this mismatch if using 3.12-only syntax.
- **Formatter & import sorting:** `ruff format` + `ruff check --fix` (`select = ["I", "F401"]`), first-party section is `diorama` (includes `diorama.backend`, `diorama.agents`, `diorama.ebook`). `pyproject.toml` still lists `black`/`isort` as dev dependencies, but there's no `[tool.black]`/`[tool.isort]` config — running them produces a different style than `ruff format` and fights it. Use ruff only.
- **Async:** pytest auto-detects async tests via `pytest-asyncio` (`asyncio_mode = "auto"`, function-scoped event loop).
- **Frontend:** `eslint-config-next` (core-web-vitals + typescript) plus the React Compiler's `react-hooks/set-state-in-effect` rule — a synchronous `setState` inside a bare `useEffect` fails lint. Browser-only facts with no natural effect (media queries, mount state, localStorage-backed preferences) are modelled with `useSyncExternalStore` instead (see `useMediaQuery.ts`, `useReaderPrefs.ts`).
